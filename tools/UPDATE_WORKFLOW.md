# 数据更新与校对

发布基准是 `src/data/`。[启动控制台](README.md) 后按以下流程更新。以下命令在仓库根目录运行，文件路径也相对于仓库根目录。

## 操作流程

1. **检查上游更新**：在独立批次中抓取、缓存并生成候选，自动校验和比较差异。任务日志显示进度与失败原因。
2. **查看差异与依据**：按名称、语言、字段筛选，对照旧值、新值、图片、来源和缓存响应，核对人工修正与英文回退。切换条目前保存备注。
3. **记录决定**：接受变更，或填写备注并选择“保留原值”“要求修正”“暂缓”。普通变更可按页批量接受；新增、删除和 ID 变化需逐项处理。
4. **修正后重建**：根据备注修改 `tools/corrections.json` 或生成规则，再“从缓存重建”；缺少响应时选“补齐缺失请求”。新批次需重新确认。“保留原值”只是修正要求，不会直接修改候选。
5. **应用并运行检查**：所有待确认项接受后，控制台写入发布数据并自动执行 `mise run check` 和 `mise run e2e`。若写入成功但检查失败，数据仍已应用，需修复后重跑检查或通过 Git 回退。
6. **导出并提交**：将导出的审核记录保存到 `tools/reports/YYYY-MM-DD.json`，与生成规则、修正表、数据和注册表的变更一起提交。控制台不操作 Git。

已应用批次只供回看。报告不含响应正文，离线复现需保留批次缓存；“当前数据”直接读取发布文件。

## 命令行与离线重建

命令行生成只创建候选，需另行运行自动校对；人工决定在控制台保存。将下例的 `<run-id>` 替换为生成日志中的批次编号，`<sha256>` 替换为自动校对输出的报告哈希。

```sh
mise run data:generate
mise run data:review -- '<run-id>'
# 在控制台确认后，使用该报告的 SHA-256 应用：
mise run data:apply -- '<run-id>' --review '<sha256>'
mise run check
mise run e2e

# 修改规则后离线重建；缺少任何响应即失败：
mise run data:generate -- --from '<run-id>'
# 复用缓存，只联网补齐缺失响应：
mise run data:generate -- --resume '<run-id>'
```

三种生成方式都创建新批次。重建后使用新编号重新校对和确认；`--from` 只保证生成阶段离线，自动校对若发现新图片地址仍需联网检查。需要全新上游状态时使用不带参数的 `data:generate`。同一 URL 的并发请求会合并并缓存，损坏缓存会报错。来源按每次请求记录获取时间，`--resume` 可能混合不同时间的响应。

批次文件位于 `tools/output/runs/<run-id>/`，随生成和校对逐步产生：

| 文件 | 用途 |
| --- | --- |
| `started.json` / `manifest.json` | 生成前的基准与源码哈希 / 全部成功后的完整来源和候选清单 |
| `cache/*.json` | 请求 URL、获取时间、响应哈希及正文 |
| `output/*.json` / `id-registry.json` | 三份候选及稳定 ID 注册表 |
| `translation-events.json` | 本地修正、依据和中间英文回退记录 |
| `review.json` / `review.md` | 校验结果、语义差异、身份变化及新图片检查 |
| `decisions.json` | 绑定报告哈希的决定、备注、版本和操作历史 |

## 生成规则与修正

范围为全国编号 `1..1025`、九世代，排除 Mega/Gmax 答案。检测到上游新增种族时生成会停止；扩展范围需同时更新生成规则与发布校验。`has-mega` 按已核实的形态限制处理：花叶蒂仅限永恒之花，基格尔德仅限完全体；详见 [Mega 形态校正](reports/2026-09-12-mega-forms.md)。

`regional` 表示同种族有地区形态，识别规则位于 `tools/fetch_pokemon_data.go`。进化条件优先匹配 `evolved_form`，再选择该形态的默认条件；无精确匹配时仅回退到未限定目标形态的条件。

翻译先拼接种族与形态名称，再按语言应用非空修正；地区名称只填补上游缺失值。输出语言代码统一小写，名称去除首尾空格。

[`corrections.json`](corrections.json) 为每项修正记录实体、语言、预期上游值、修正值、理由、来源和核对日期。上游原值改变会中止生成，需重新核对修正规则。报告保留中间英文回退记录，`remaining_english_fallbacks` 仅列最终仍存在的回退。

## 校验与发布约束

语义比较按名称对齐数据；忽略对象键顺序，将特性、标签、恶作剧图片作为集合，`tags: null` 与 `[]` 等价。属性槽位顺序仍有意义。新增、删除和身份变化单独标记。

自动校验覆盖种族完整性、ID/名称唯一性、注册表、世代、属性、种族值及总和、九语言名称和界面引用、地区形态标签，以及已确认的翻译/进化样例。自动校对会下载相对发布数据新增的图片 URL，检查 HTTP 状态、内容类型并记录正文哈希；相同 URL 的内容变化不会触发重查。结构检查不能代替语言校对。

应用同时要求匹配的报告哈希与人工决定。任何待确认或未接受项都会阻止应用。重新校对保留历史并清空当前决定；来源、规则或候选改变需重建；发布基准改变后旧批次失效。审核版本和批次锁防止多个页面或命令互相覆盖。

应用前复验所有哈希，写入三个游戏 JSON、`src/data/dataset.json` 和 `tools/id-registry.json`。注册表保留历史 ID，新名称只追加；知识文章不在发布范围。浏览器的数据版本与存档行为见[根目录说明](../README.md#代码与数据)。

写入先暂存再逐项替换，普通 I/O 失败时尝试恢复原内容；强制终止或断电可能造成部分写入。此时执行 `mise run data:verify`，通过 Git 恢复一致状态后重试。锁残留时先确认没有相关进程运行，再移除 `tools/output/apply.lock` 或批次内 `decisions.lock`。

CI 的 `mise run check` 使用本地数据和测试夹具，不自动抓取或发布。
